## Commands

Package manager is **pnpm** (`packageManager: pnpm@9.4.0`).

```bash
pnpm dev      # next dev — http://localhost:3000
pnpm build    # next build — also the de facto type-check gate
pnpm start    # serve the production build
pnpm lint     # eslint (flat config, no args needed)
```

No test runner and no `typecheck` script are configured. To type-check alone:
`pnpm exec tsc --noEmit`.

## State of the project

`app/` is still the untouched `create-next-app` landing page — there is no application
code, data layer, or API yet. The notes below describe conventions already baked into the
scaffold and the workflow in `skills/`, not existing architecture to imitate.

## Next.js 16 specifics

`AGENTS.md` (imported above) is the authority: this Next.js version has breaking changes
relative to older knowledge. Read the relevant guide under `node_modules/next/dist/docs/`
before writing routing, data-fetching, caching, or metadata code.

- **Generated route types.** `app/layout.tsx` uses the global `LayoutProps<"/">` rather
  than a hand-written props type. Next generates these into `.next/types` and
  `.next/dev/types` (both in `tsconfig.json`'s `include`), so use the generated
  `LayoutProps`/`PageProps` helpers for new layouts and pages. They don't exist until
  `next dev` or `next build` has run — a cold clone type-errors until then.
- **Tailwind CSS v4** via PostCSS (`postcss.config.mjs` → `@tailwindcss/postcss`). There is
  deliberately no `tailwind.config.*`: theme tokens live in `app/globals.css` under
  `@import "tailwindcss"` and the `@theme inline { … }` block. Add design tokens there, not
  in a JS config. Dark mode is `prefers-color-scheme`-driven, redefining the
  `--background` / `--foreground` CSS variables.
- **Fonts** load via `next/font/google` in `app/layout.tsx` and are exposed as CSS
  variables (`--font-inter`, `--font-geist-mono`) that the `@theme` block consumes.
- `@/*` is aliased to the repo root. TypeScript is `strict`.
- ESLint uses flat config (`eslint.config.mjs`) composing `eslint-config-next/core-web-vitals`
  and `eslint-config-next/typescript`.

## The `skills/` workflow

`skills/` holds five custom skill definitions that describe an intended
build-review-remember loop for this project. They form a pipeline, and several of them
read and write shared markdown artifacts in the **project root**:

| Skill | Role | Artifact |
| --- | --- | --- |
| `architect` | Plan a feature before coding; align on vocabulary, surface decisions, produce a plan the developer confirms | — |
| `imprint` | After building UI, extract visual patterns so later components match earlier ones | writes `ui-registry.md` |
| `review` | After a feature, verify it matches the plan and the design/architecture standards; **reports only, never fixes** | reads the `architect` plan |
| `recover` | Diagnose a failure's *type* before responding — targeted fix vs. hard reset vs. rethink | — |
| `remember` | Save session state at the end, restore it at the start | reads/writes `memory.md` |

Consequences worth knowing:

- `ui-registry.md` is the source of truth for UI consistency. Read it before writing any
  component, and match the existing spacing/color/radius patterns rather than inventing new
  ones. `imprint` is meant to run after every UI component.
- `memory.md` holds the most recent session state and is overwritten, not appended.
  `remember` explicitly forbids persisting secrets — redact credential-like values to
  placeholders such as `[REDACTED_API_KEY]` instead.
- `review` deliberately reports without fixing, so the developer decides what matters.

Note: these live in `skills/`, not `.claude/skills/`, so Claude Code does not auto-discover
them as invocable skills — read the relevant `SKILL.md` directly, or move the directory to
`.claude/skills/` to make `/architect`, `/review`, etc. work as slash commands. `skills/` is
currently untracked in git.

## AGENTS.md churn

`AGENTS.md` is regenerated by `next dev` (see
`node_modules/next/dist/server/lib/generate-agent-files.js`). Removing it from a diff only
recreates the uncommitted change — commit it alongside your work to keep the tree clean.
